Alexa Shopping · Platform engineering

Self-Service Campaign Platform

Every Alexa proactive-notification campaign used to need engineers in the loop — a 3-day, multi-team process. I led the design and build of a greenfield portal that made it a 2-hour self-service flow, now used by 10+ teams across multiple notification channels.

94% faster launches 7M+ MAU reached 24h → <1 min access grants
Architecture deep dive
  • Spring Boot service on ECS Fargate acts as the orchestration layer between the portal UI and downstream notification systems, supporting multiple delivery channels (device notifications, shopping hints, ambient home cards).
  • Event-driven fan-out: audience-segment updates land on a segments queue (SQS); a producer task expands each segment into per-customer messages on a notifications queue; consumer tasks build payloads and invoke downstream delivery APIs. Each stage scales horizontally and fails independently.
  • OIDC authentication through an internal identity broker, enforced by a servlet security filter with DynamoDB-backed sessions.
  • Campaigns modeled as first-class resources in a centralized entitlement system — per-campaign view / update / test / execute / delete permissions, granted self-service with no manual approvals.

Amazon Compensation · Architecture

Multi-Tenant Compensation Platform

Amazon's step-plan compensation system was built for exactly one business. I re-architected it into a multi-tenant platform — tenant identity end to end, configurable workflow components in place of a monolithic processor — scaling from 1M to 2M employees with 2 business units onboarded and 7 planned.

48M records, zero downtime 1M → 2M employees −70% onboarding time
Architecture deep dive
  • Introduced a business identifier through every service, table, and event in the platform, giving each tenant isolation plus configuration-driven business logic.
  • Replaced a monolithic if/else processor with Strategy-pattern processors per workflow — wage change, tenure progression, audit — selected at runtime; each is independently testable and extensible.
  • Zero-downtime backfill of 48M DynamoDB production records using AWS Glue, with validation and reconciliation scripts proving 100% data consistency.
  • Partnered with BI and compensation teams to onboard the first 2 business units of 7 planned.

Amazon Compensation · Reliability

Shift-Differential API — Fault-Tolerant Redesign

The API computing employee shift premiums depended on precomputed pattern combinations — and missing combinations meant empty responses. Roughly 4% of calculations were wrong, with direct payroll impact. I redesigned it around a multi-stage fallback and a serverless migration.

4% → 0.3% error rate $1.3M saved per year −27% P50 latency
Architecture deep dive
  • Multi-stage lookup: when the primary precomputed DynamoDB lookup misses, the system derives the shift-differential value dynamically from secondary lookup tables instead of returning empty.
  • Migrated the AppSync API from pipeline resolvers to a Lambda-based architecture after a proof-of-concept tradeoff evaluation — the better fit for complex orchestration logic and future extensibility.
  • Phased rollout behind AWS AppConfig feature flags with automatic rollback, decoupling the data-source transition from business logic — zero service interruption during migration.
